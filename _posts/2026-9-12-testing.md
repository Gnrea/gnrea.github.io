# **The actual post**
Fixing an USB, for those that broke a USB usling Fdisk like me
1. click the "search" bar or hit the "Windows" key 
2. then type diskpart and find diskpart.exe windows tool
3. in the diskpart type list disk, 
  if your USB is plugged in you should see it show up. Mine was corrupted and didn't exist in linux, but it worked here
4. select disk 1
  I only had 1 external disk/USB and disk 0 was the default "C: Drive"
5. Clean all
  Note this will manually wipe everything, similar to what I was accomplishing with fdsik and useing /dev/null to zero out the USB
  Also my 128 GB USB 3 had a consistent speed around 20 MB/s so that means 5 seconds for 0.1 gig x 10 x 128 around
  so it's going to take a bit, 6400 seconds or about 2 hrs (7200 seconds) give or take
  To make sure you're seeing data working you can go to task manager and under disks you will see your USB as Disk 1 in my case.
  I was able to use that to see, speed and latency for reading/writing data. This helped me estimate how long the process would take.
6. Create partition primary
  Make sure the right disk is still selected and this brought up the quick partition scheme for me
  I accepted defaults, which was D: drive label, and exFAT. It showed up in the windows drive again so I belive it's fixed
7. Break/Brick the USB again (the loop)
  As I keep learning, I keep finding new ways to fail wiping a USB.
  The easiest way to wipe is probably just using "Rufus" and having it overwrite everything
  But I like my CLI tools like "fdisk" and I haven't completly bricked my USB yet ...
